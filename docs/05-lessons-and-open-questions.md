# 05. 교훈, 열린 질문, 다음 단계

## 1. 문헌에서 얻은 교훈

1. **단순하게 시작한다.**
   통일 평가에서 많은 라우팅 방법이 비슷했고, 일부는 단순 기준선을 안정적으로 이기지 못했다 (LLMRouterBench).
   태스크 유형 조회표 + 규칙 + 소형 분류기로 시작하고, 복잡한 방법은 기준선을 이길 때만 들인다.

2. **후보 모델은 적게, 신중하게 고른다.**
   앙상블을 키우는 것보다 후보를 신중히 고르는 것이 낫다 (LLMRouterBench).
   부류는 3개(경량 / 표준 / 중량) 정도로 시작한다 (Triage도 3티어).

3. **쿼리 텍스트만으로는 한계가 있다.**
   설명만 보는 라우터에는 오분류 하한이 있다 (SWE-Router).
   모델 실행 없는 컨텍스트 신호(저장소 검색, 코드 지표)를 넣는다 (Triage).

4. **정보 부족이 병목이다.**
   태스크 차원별 성능 통계를 주는 것만으로 큰 개선이 있었다 (Agent-as-a-Router).
   → 모델 쪽 성적표를 만드는 일이 라우터 알고리즘보다 먼저다.

5. **측정은 분포로 한다.**
   응답 한 번으로 만든 라벨은 불안정하다. 반복 측정으로 기대값과 변동성을 본다 (DARS).

6. **해석 가능성을 유지한다.**
   IRT식 능력/난이도 값, 난이도 분석 문장, 자연어 추천 이유는 디버깅과 신뢰 형성에 중요하다 (IRT-Router, VDAR-Router, BELLA).

7. **분류는 작은 모델로 충분하다.**
   1.5B 모델로 유형·선호 매핑이 가능했다 (Arch-Router). 분석 비용은 태스크 비용보다 훨씬 작아야 한다.

8. **콜드 스타트는 시드 세트로 푼다.**
   대표 태스크를 모든 후보로 실행해 경험 기억을 만든다 (BoundaryRouter, IRT-Router 워밍업).

9. **지시 형태가 모델 역량을 바꾼다.**
   작은 모델은 자유 서술 지시와 정형 지시 사이 성능 차이가 크다 (NVIDIA tao 스킬 측정).
   모델 측정 시 지시 형태를 통제하거나 변수로 기록한다.

## 2. 열린 질문

| # | 질문 | 왜 중요한가 |
|---|---|---|
| Q1 | 주로 다루는 태스크 유형 분류(도메인 × 행위)를 어떻게 정할까? | 모든 측정과 조회표의 기준 축 |
| Q2 | 모델 부류를 몇 개로, 어떤 모델로 구성할까? | 후보가 적고 명확할수록 라우팅이 쉽다 |
| Q3 | 성공 판정을 어떻게 할까? 결정적 검증이 없는 유형은? | 라벨 품질이 라우터 품질의 상한 |
| Q4 | 데이터 민감도를 어떤 규칙으로 판정할까? | 위반 시 비용이 가장 큰 제약 |
| Q5 | 분석기는 규칙 / 소형 모델 / 하이브리드 중 무엇으로? | 분석 비용과 정확도의 균형 |
| Q6 | 목표 품질 `τ`를 태스크 유형별로 어떻게 정할까? | 운영점 결정 |
| Q7 | 범위 추정용 컨텍스트 신호 중 무엇이 실제로 구분력이 있나? | 쿼리 단독 판단의 한계 보완 |
| Q8 | 라우터를 어디에 붙일까? (에이전트 하네스 확장, 프록시, CLI 래퍼) | **해결**: pi virtual model. Q10~Q13은 [06 문서 §6](06-literature-update-pi-plugin.md) 참고 |
| Q9 | 세션 고정에서 재실행 비용을 어떻게 최소화할까? | 과소 배정의 대가 |

## 3. 정독 우선순위

> 1~8은 2026-11에 본문을 검토했다. 결과는 [06 문서 §1](06-literature-update-pi-plugin.md)에 있다.

|---|---|---|

| 2 | Triage (2604.07494) | 코드 건강도 하위 지표 목록, 휴리스틱 임계값, 성립 조건 유도 |

| 5 | DARS (2606.06924) | 반복 측정 수, 변동성 요약 방식 |
| 6 | Agent-as-a-Router (2606.22902) | "태스크 차원"의 정의, CodeRouterBench 구성 |
| 7 | VDAR-Router (2607.18098) | 난이도 분석 프롬프트, 검색 방식 |
| 8 | BELLA (2602.02386) | 역량 추출·군집화 절차 |
